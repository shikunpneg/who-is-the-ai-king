1. Transformer 三大范式

2017 年 Google 在《Attention Is All You Need》中提出 Transformer 后，社区逐渐分化为三条技术路线。它们的核心差异在于"如何堆叠编码器和解码器"。

1.1 Encoder-only（编码器专用）

仅使用 Transformer 编码器，输入序列通过双向自注意力处理。适合理解类任务（分类、实体识别、语义搜索）。

  • 代表模型：BERT（Google, 2018）、RoBERTa（Meta, 2019）、DeBERTa
  • 优势：双向注意力可看到完整上下文，理解精度高
  • 局限：无法自回归生成文本，不适合对话/写作场景
  • 现状：作为"特征提取器"嵌入到 RAG pipeline 或分类系统中，仍是搜索和推荐的核心组件

1.2 Decoder-only（解码器专用）

仅使用 Transformer 解码器，通过因果（单向）注意力逐 token 生成。是当前 LLM 的绝对主流，占据 90%+ 以上的旗舰模型。

  • 代表模型：GPT 系列（OpenAI）、Llama（Meta）、DeepSeek、Qwen、Claude
  • 优势：天然支持自回归生成，统一架构处理所有任务
  • 关键设计：因果注意力掩码 + KV Cache 实现高效推理
  • 规模：从 1B 到 1.6T 参数，覆盖端侧到数据中心

1.3 Encoder-Decoder（编码器-解码器）

同时使用编码器和解码器，编码器处理输入序列，解码器生成输出序列。适合序列到序列转换任务。

  • 代表模型：T5（Google, 2020）、BART（Meta, 2019）
  • 优势：在翻译、摘要等任务上精度最高
  • 局限：架构复杂，推理成本高，难以规模化到千亿参数
  • 现状：在垂直场景（翻译、DNA 序列分析）仍有使用，但在通用 LLM 赛道已被 Decoder-only 取代

2. 注意力机制演进

自注意力是 Transformer 的核心。但"如何计算 Q、K、V"的工程选择，直接决定了推理成本。过去 5 年的演进主线只有一条：在保持模型质量的前提下，压缩 KV Cache。

2.1 四种注意力变体对比

变体 Q 投影 K 投影 V 投影 KV Cache 大小 推理速度 模型质量 代表模型
MHA 多头 h 个头 h 个头 h 个头 100% 4/10 9.5/10 原始 Transformer、BERT
MQA 共享 h 个头 1 组 1 组 ~17% 8/10 6.5/10 PaLM、Gemini Flash
GQA 分组 h 个头 g 组 g 组 ~33% 6.5/10 8.5/10 Llama 3、Mistral、Qwen
MLA 潜在 h 个头 低秩压缩 低秩压缩 ~8% 9.5/10 9/10 DeepSeek-V2/V3/V4
核心洞察：MQA 虽然 KV Cache 最小，但模型质量损失明显；GQA 是当前工业界的"甜蜜点"； MLA（DeepSeek 提出）则通过低秩压缩技术，同时实现了"最小 KV Cache + 最高质量"，代表了注意力优化的最新方向。

2.2 KV Cache 为什么重要？

自回归推理时，每个新 token 都要与所有历史 token 做注意力计算。KV Cache 缓存了历史 token 的 K 和 V，避免重复计算。

KV Cache 大小 = 2 × 层数 × 隐藏维度 × token 数 × 字节数

在长文本场景（128K tokens），KV Cache 可占据 90%+ 的显存。这就是为什么注意力变体的选择，直接决定了"能跑多长的文本"和"单次推理成本"。

3. 前馈网络（FFN）变体

Transformer 的注意力层负责"信息交互"，FFN 层负责"信息存储"。FFN 占模型总参数的 2/3，其设计直接影响模型的知识容量和推理效率。

3.1 四种 FFN 架构对比

变体 公式 参数效率 推理速度 代表模型 说明
Standard FFN W₂·σ(W₁·x) 基准 基准 原始 Transformer、BERT 两层全连接 + ReLU 激活，最简单的 FFN 形式
SwiGLU (W₁·x ⊙ Swish(W₂·x)) · W₃ 高 快 Llama、PaLM、Gemini 门控机制 + Swish 激活，当前工业界标配
GeGLU (W₁·x ⊙ GELU(W₂·x)) · W₃ 高 快 PaLM、部分 BERT 变体 与 SwiGLU 类似，使用 GELU 替代 Swish
Gated MLP (W₁·x ⊙ W₂·x) · W₃ 最高 最快 部分最新模型 简化版门控，去掉了非线性激活
为什么 SwiGLU 赢了？门控机制（Gating）让模型学会"选择性激活"——某些维度在特定任务上更重要。 实验证明：在相同参数量下，SwiGLU 的知识容量比 Standard FFN 高 15-20%。

3.2 门控机制的直觉

传统 FFN 是"全有或全无"的激活模式。SwiGLU 引入了一个"门控分支"，让模型学会对不同输入动态调整激活强度：

# SwiGLU 伪代码
gate = Swish(x @ W_gate)    # 门控信号：哪些维度需要激活
up = x @ W_up               # 上投影：扩展到高维
output = (gate * up) @ W_down  # 门控 × 投影 → 下投影

这种"信息流控制"的设计理念，与注意力机制中的"信息流控制"异曲同工，构成了现代 LLM 的双层调控体系。

4. 归一化方法

归一化层虽小，但直接影响训练稳定性和最终性能。不同归一化方法的选择，反映了"训练稳定性"与"推理速度"之间的权衡。

4.1 五种归一化方法对比

方法 归一化维度 可学习参数 训练稳定性 推理速度 代表模型
LayerNorm 特征维度 有（γ, β） 高 慢 原始 Transformer、BERT
RMSNorm 特征维度 仅有 γ 中 快 Llama、Mistral、DeepSeek
DeepNorm 特征维度 有（缩放） 极高 中 DeepSeek（早期版本）
Sandwich Norm 特征维度 有（多组） 极高 慢 研究性质
QK-Norm 注意力 Q/K 有 中 快 Gemma、部分新模型

4.2 RMSNorm 为什么成为主流？

RMSNorm（Root Mean Square Layer Normalization）的公式极简：

RMSNorm(x) = x / sqrt(mean(x²) + ε) × γ

与 LayerNorm 相比，RMSNorm 去掉了均值中心化（只做方差归一化），推理速度提升显著。在大规模训练中，这种微小差异累积起来就是巨大的效率差距。

当前工业界的共识：RMSNorm + SwiGLU + RoPE 已成为 Llama 系模型的"三件套"，被绝大多数开源模型采纳。

4.3 QK-Norm 的特殊价值

QK-Norm 在注意力计算前，对 Q 和 K 分别做归一化。它的作用是防止注意力分数过大导致的梯度消失/爆炸。

Google 的 Gemini 和 Gemma 系列使用了 QK-Norm，是"训练稳定性优化"的重要补充手段。

5. 位置编码

Transformer 本身没有"序列顺序"的概念——所有 token 同时处理。位置编码就是给模型注入" token 在序列中的位置信息"。如何让模型理解"第 100 万 token 和第 1 token 的相对关系"，是位置编码的核心挑战。

5.1 六种位置编码对比

方法 核心思想 外推能力 计算开销 实现复杂度 代表模型
Absolute PE 为每个绝对位置学习一个向量 2/10 低 简单 原始 Transformer
Sinusoidal 三角函数生成位置编码 5/10 极低 极简 原始 Transformer
RoPE 旋转位置编码，通过旋转矩阵编码相对位置 7/10 中 中 Llama、Qwen、Mistral
ALiBi 线性偏置，直接在注意力分数上加距离惩罚 9/10 极低 极简 BLOOM、MPT
YaRN NTK-aware + 频率缩放，RoPE 的扩展 10/10 低 低 Llama 2 Long、Qwen2
NoPE 不显式编码位置，靠注意力隐式学习 3/10 零 零 部分研究模型

5.2 RoPE 为什么是当前主流？

RoPE（Rotary Position Embedding）的核心思想是：将位置信息编码为向量的旋转角度。

# RoPE 核心公式（简化）
# 对位置 m 和 n，它们的相对位置编码 = 旋转 (m - n) 个角度
# 这天然编码了"相对位置"而非"绝对位置"

ROPE(q_m, k_n) = (q_m · R_θ^(m-n)) · (k_n · R_θ^(m-n))^T

RoPE 的优势：

  • 相对位置感知：两个 token 的注意力分数只取决于它们的相对距离，符合直觉
  • 衰减特性：距离越远，旋转角度越大，注意力分数自然衰减
  • 可扩展：通过 YaRN 等技术，可在训练长度基础上外推 4-8 倍

5.3 ALiBi 的意外成功

ALiBi（Attention with Linear Biases）在 2022 年提出时被视为"过于简单"——它只是在注意力分数上减去一个与距离成正比的偏置。

但实验表明：这个"简单"方法在短文本训练后，外推能力远超 RoPE。BLOOM（176B）使用 ALiBi 训练，可在 1024 tokens 训练后直接推理 2048+ tokens 而不损失性能。

虽然 ALiBi 最终未成为主流（RoPE 的生态更完善），但它的"简单即美"理念深刻影响了后续设计。

6. 新型架构：超越 Transformer

Transformer 的核心瓶颈是 注意力的 O(n²) 复杂度——序列长度翻倍，计算量翻四倍。这催生了三类"去注意力化"的探索：状态空间模型（SSM）、长卷积、以及混合架构。

6.1 三种替代架构对比

架构 核心机制 复杂度 优势 局限 代表模型
RWKV 线性注意力 + RNN 风格并行化 O(n) 推理极快、训练可并行 长程建模弱于注意力 RWKV-6/7
Mamba 选择性状态空间模型 O(n) 线性复杂度 + 选择性遗忘 训练不稳定、生态不成熟 Mamba-2
Hyena 隐式长卷积 + 门控 O(n log n) FFT 加速、训练快 实现复杂 Hyena H2O

6.2 混合架构：当前最务实的选择

纯 Transformer、纯 SSM、纯卷积各有优劣。当前最前沿的方案是层间混合——在不同层使用不同机制：

模型架构组成总参数活跃参数设计理念
Jamba (AI21 Labs) Transformer + Mamba 混合 398B 52B 每 4 层中 3 层 Transformer + 1 层 Mamba，交替排列
StripedHydra (Together) 注意力 + SSM + 卷积 混合 2.8B 2.8B 层内并行多条"专家路径"，各取所长
FG-VQA Flash Attention + Gated DeltaNet 未公开 未公开 注意力层加速 + DeltaNet 替代部分 FFN
Jamba 的设计哲学：不是所有层都需要同等强度的注意力。"关键层"用 Transformer 保证推理精度，"普通层"用 Mamba 降低计算成本。这种"按需分配"的策略，可能是下一代架构的主流方向。

6.3 RWKV：最成熟的 RNN 替代方案

RWKV（Receptance Weighted Key-Value）是当前最接近"Transformer 级性能"的 RNN 架构：

  • 训练：可在 GPU 上并行训练（通过 Transformer 风格的并行公式）
  • 推理：像 RNN 一样逐 token 递推，无需 KV Cache，内存占用恒定
  • 性能：RWKV-7 在多项 benchmark 上接近同参数的 Transformer
  • 生态：完全开源，社区活跃，已适配 llama.cpp、Ollama 等主流推理框架

7. 架构选择的黄金标准

经历了 7 年的架构演进，工业界在 2025-2026 年形成了一个"事实标准"。这不是某个公司的独创，而是多家头部公司独立收敛到同一配方的结果。

独立收敛到同一配方

为什么这个配方能赢？它不是理论最优，而是工程最优——在训练稳定性、推理速度、模型质量、生态系统四个维度上达到了最佳平衡。每个组件都有成熟的开源实现和丰富的调优经验。

给技术决策者：在选择模型时，不要只看参数规模——更应关注活跃参数（推理成本的真实反映）和上下文长度（决定可处理的文本规模）。MoE 模型的总参数是"虚胖"，活跃参数才是"真金白银"。

🎯 给技术决策者的 3 条核心建议

  1. 先看推理成本，再看参数规模：架构选择直接决定"单位 token 成本"——GQA vs MHA 的 KV Cache 差异可达 3-5 倍。
  2. 关注"活跃参数"而非"总参数"：MoE 模型的总参数量是误导性指标，活跃参数才是推理成本的真实反映。
  3. 组合 > 单一：混合架构（Transformer + SSM）是当前最前沿的方向，Jamba 等模型证明了"按需分配层类型"的可行性。
