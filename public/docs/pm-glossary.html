2. 各 Benchmark 详解

大模型评测不是"一个分数定乾坤"。理解每个 benchmark 的测量目标、题目来源与局限，才能正确解读 tracker 中的数字。

2.1 LiveBench — 动态能力排名

🔄 实时
评测特点
题目随时间更新，避免模型"背题"，是目前最诚实的客观评测之一。
📊 6 大类
覆盖范围
推理、数学、编程、语言理解、知识、指令遵循。
📈 排名
呈现形式
Tracker 中以 livebench_overall 排名呈现，数字越小越强。

2.2 SWE-bench Verified — 编程能力金标准

定义：SWE-bench 是从真实 GitHub issue 构建的软件工程任务集。Verified 版本由人工审核确保题目质量。

📌 分数含义：68.5% 表示该模型在 500 个真实软件工程任务中，成功生成被接受的 PR 的比例。

2.3 MMLU-Pro — 知识广度试金石

定义：Massive Multitask Language Understanding（进阶版），覆盖 43 个学科、12,000 道题目。

与 MMLU 的区别：Pro 版本去除了"仅靠记忆可答"的题目，增加了 10 个选项的多选难度，更能反映真实推理水平。

各公司 MMLU-Pro 得分对比

2.4 GPQA Diamond — 研究生级推理

定义：GPQA（Google-Proof Q&A Benchmark）由领域专家出题，Diamond 是最难的子集。题目涉及物理、化学、生物等需要深度推理的学科。

为什么重要：常规 benchmark 已被模型"刷爆"，GPQA Diamond 是少数仍能区分顶尖模型能力的评测。

解读示例：GPQA Diamond 82.1% 不仅考察知识记忆，更要求模型在多个候选答案中进行"排除法 + 推理链"的复合思考。

2.5 BBH — 复杂推理任务集

定义：BIG-Bench Hard，从 BIG-Bench 中精选的 23 个"最难"任务，涵盖算法推理、逻辑谜题、语义解析等。

特点：每个任务都需要多步推理，而非单步匹配，是衡量模型"思维链"能力的关键指标。

2.6 MATH / AIME — 数学竞赛级推理

定义：MATH 数据集包含 12,500 道高中竞赛题；AIME（美国数学邀请赛）是 15 道填空题的高难度竞赛。

分数含义：模型直接输出最终答案的准确率。通常需要配合 chain-of-thought 才能获得高分。

各公司 MATH/AIME 正确率

2.7 HumanEval+ — 代码生成准确率

定义：HumanEval 的扩展版，包含 164 个 Python 编程问题，每个问题有多个测试用例。pass@1 是最常用的指标。

局限：仅覆盖 Python、仅覆盖函数体编写，无法反映真实软件工程的全貌（因此 SWE-bench 更具说服力）。

2.8 SuperCLUE — 中文大模型权威评测

定义：中文大模型基准评测（CLUE 的升级版），从理解、推理、代码、知识等维度综合评分。

特点：专为中文场景设计，题目和语料均来自中文社区，是中文赛道最重要的横向对比工具。

3. MAU 深度解读

月活用户（Monthly Active Users）是衡量 AI 产品市场渗透率的核心指标。但对于 LLM 产品，MAU 的统计远比传统 App 复杂——没有统一的"官方 MAU"数据源，需要多源三角测量。

3.1 什么是 MAU？

定义：MAU = 在过去 30 天内，至少使用过一次该产品/服务的独立用户数量。

📐 日粒度
DAU / MAU 比
反映用户粘性。比值越高说明"当天回访率"越强。
📈 增长率
MoM / YoY
月环比 / 年同比增长，判断是加速还是减速。
⚠️ 坑
去重逻辑
不同厂商的设备 ID / 账号 ID 去重方式不同，跨平台对比 MAU 需谨慎。

3.2 多源 MAU 三角测量方法论

LLM Tracker 采用 4 个独立数据源交叉验证 MAU，每个来源的可信度和覆盖范围不同：

数据源权重可信度覆盖范围局限
官方公布 MAU50%高全量用户可能选择性披露
Sensor Tower20%高移动端 App不含 Web / API
OpenRouter 市占率20%中第三方平台仅覆盖 OpenRouter 用户
Artificial Analysis Index10%中综合 API 流量指数非绝对值

3.3 Adoption Score（采用度得分）计算

基于上述 4 个数据源，按权重计算 0-100 的综合得分：

Adoption Score =
  log10(official_mau) / log10(2000) × 50   ← 官方 MAU（对数缩放）
+ log10(sensor_tower_mau) / log10(2000) × 20 ← Sensor Tower
+ (openrouter_share_pct / 20) × 15          ← OpenRouter 市占
+ (aa_index / 100) × 10                    ← AA Index
+ (lmarena_elo / 1700) × 5                 ← LMArena Elo
设计思路：MAU 绝对值差异巨大（从百万到十亿级），使用对数缩放避免"大者通吃"。 权重分配反映数据源可信度：官方数据 > 独立第三方 > 平台内指标。

4. 参数估计方法论

OpenAI、Anthropic 等头部公司从不公开模型参数量。LLM Tracker 采用三种间接估计方法，并给出置信区间。

flowchart LR

    A --> C[方法2: IKP 不可压缩知识探测]
    A --> D[方法3: 记忆化探测]
    
    B --> E[拟合价格-参数量曲线]
    C --> F[测量有效知识容量]
    D --> G[测试罕见事实记忆率]

    G --> H
    
    H --> I{可信度分级}
    I --> J[High: 多方法一致]
    I --> K[Medium: 两方法交叉]
    I --> L[Low: 单一方法]
    
    J --> M[输出: 参数量 + CI]
    K --> M
    L --> M

4.1 方法一：API 定价回归法

原理：模型的 API 定价与参数量呈正相关。通过收集各公司的 API 输入/输出价格，拟合"价格-参数量"回归曲线。

优势：数据公开可查，适合快速估算。

局限：定价策略受商业因素影响（竞争、市场定位），并非纯技术成本驱动。

4.2 方法二：IKP（不可压缩知识探测）

原理：通过"知识探测"测量模型的知识容量。核心思想：模型能存储多少不可压缩的"事实"，与参数量呈线性关系。

来源：由 Anthropic 的 researchers 提出，通过测量模型的"有效参数"来反推总参数量。

优势：不依赖公司披露，纯技术测量。

局限：需要大量 API 调用，成本高、周期长。

4.3 方法三：记忆化探测（Memorization Probes）

原理：向模型输入"罕见事实"（如随机生成的实体-关系对），测试模型能否记住。通过记忆容量反推参数量。

来源：DeepMind 的研究指出，模型记忆的"事实量"约为参数量的 1-2 倍。

优势：可验证性强，方法论公开。

局限：受训练数据分布影响大，不同领域的记忆率差异显著。

4.4 置信区间与可信度分级

每种方法都有误差范围，综合多种方法后给出：

High
高可信度
多种方法一致 + 公司半官方确认。如 DeepSeek V4-Pro 1.6T/49B。
Medium
中可信度
两种方法交叉验证，有一定偏差。如 OpenAI GPT-5.6 Sol。
Low
低可信度
仅单一方法或数据源不足。仅供方向性参考。

5. 产品经理 AI/LLM 专业术语表

AI 产品 PM 需要跨越"技术理解"与"商业判断"的鸿沟。以下按类别整理必须掌握的 50+ 专业缩写。

5.1 模型架构与技术缩写

Transformer TF

2017 年 Google 提出的序列到序列架构，通过自注意力机制替代 RNN，是所有现代 LLM 的基础。

Mixture of Experts MoE

混合专家架构。将大模型拆分为多个"专家"子网络，推理时仅激活部分专家，实现"大参数、低推理成本"。

Multi-Head Attention MHA

多头注意力。并行使用多个注意力"头"，从不同子空间捕捉序列关系。

Grouped-Query Attention GQA

分组查询注意力。MHA 与 MQA 的折中方案，平衡推理速度与质量。

Multi-Query Attention MQA

多查询注意力。所有头共享同一组 KV，大幅减少推理内存，但质量略降。

DeepSeek Shared Attention DSA

DeepSeek 提出的注意力优化，在长文本场景下显著降低计算量。

Multi-head Latent Attention MLA

多头潜在注意力。DeepSeek-V2 引入的 KV cache 压缩技术，是 MoE 推理效率的关键。

Retrieval-Augmented Generation RAG

检索增强生成。先检索外部知识库，再让 LLM 基于检索结果生成回答，是提升事实准确性的主流方案。

Chain-of-Thought CoT

思维链。在 prompt 中显式要求模型"一步步推理"，显著提升复杂任务正确率。

Reinforcement Learning from Human Feedback RLHF

基于人类反馈的强化学习。用人类偏好训练奖励模型，再用 PPO 优化 LLM，是 ChatGPT 对齐的核心技术。

Direct Preference Optimization DPO

直接偏好优化。RLHF 的简化版，不需要显式训练奖励模型，直接从偏好数据优化 LLM。

Low-Rank Adaptation LoRA

低秩适配。在原始权重旁插入可训练的"低秩矩阵"，以极低参数量微调大模型，是私有化部署的标配。

Quantization GPTQ / AWQ

量化。将模型权重从 FP16 压缩到 INT4/INT8，减少内存占用，可在消费级 GPU 运行大模型。

Flash Attention

由 Tri Dao 提出的注意力算法优化，通过 IO 感知的块计算大幅减少显存读写，是长文本推理的关键技术。

5.2 商业、增长与运营缩写

Monthly Active Users MAU

月活用户。过去 30 天内使用过产品的独立用户数，衡量市场渗透率的核心指标。

Daily Active Users DAU

日活用户。过去 24 小时内使用过产品的独立用户数，衡量用户粘性。

Annual Recurring Revenue ARR

年经常性收入。SaaS / API 收入的标准化指标，反映年度经常性收入规模。

Customer Acquisition Cost CAC

客户获取成本。总营销销售费用 / 新增客户数，衡量获客效率。

Lifetime Value LTV

客户生命周期价值。单个客户在其生命周期内贡献的总毛利。

LTV / CAC Ratio

客户价值与获客成本比。>3 是健康 SaaS 的基准线，>10 是卓越表现。

Net Revenue Retention NRR

净收入留存率。衡量现有客户的收入增减，是 SaaS 产品市场匹配的核心指标。

Churn Rate CR

流失率。周期内流失客户数 / 期初客户数。分"客户流失"和"收入流失"。

Product-Market Fit PMF

产品市场匹配。40% 以上用户表示"没有这个产品我会很失望"是经典判断标准。

Usage-Based Pricing UBP

按 usage 计费。LLM API 的主流定价模式（按 token 数量计费），区别于固定订阅。

Token

LLM 的基本计费单位。1 token ≈ 4 字符英文 / 1.5 字符中文。Token 限制（Context Window）是模型能力的关键参数。

Cost per Million Tokens

百万 token 成本。API 定价的核心比较维度。过去两年下降了 90%+。

Free Trial / Freemium

免费试用 / 免费增值。LLM 产品的主流获客策略：免费层吸引用户，付费层实现变现。

API-First Strategy

以 API 为第一入口的产品策略。LLM 公司的核心商业模式，通过 API 调用量收费。

5.3 评测、数据与基础设施缩写

Artificial Analysis Index AA Index

AI 模型综合质量指数（0-100），由 artificialanalysis.ai 维护，整合 10+ 项 benchmark。

Big-Bench Hard BBH

23 个 BIG-Bench 最难任务的集合，评估复杂推理能力。

HuggingFace HF

全球最大的开源模型社区，是 LLM 模型分发与评测的核心基础设施。

Parameter P

模型参数量。B（十亿）/ T（万亿）为单位。参数量是模型能力的"天花板"。

FLOPs

浮点运算次数。衡量训练/推理计算量的客观指标，与参数量、序列长度相关。

Context Window

上下文窗口。模型一次能处理的最大 token 数，是长文本能力的决定因素。

Few-shot / Zero-shot

少样本 / 零样本。Zero-shot 不给示例直接问；Few-shot 给几个示例再问。

Instruction Tuning

指令微调。在预训练后，用"指令-回答"对模型进行有监督微调，使模型能理解人类意图。

Constitutional AI CAI

宪法式 AI。Anthropic 提出的对齐方法，用一套"宪法原则"指导模型自我修正而非依赖人类标注。

OpenAI API兼容 OAIC

第三方模型服务兼容 OpenAI API 格式，是 OpenRouter 等平台能聚合多家模型的关键。

5.4 组织、战略与产品模式

Foundational Model

基础模型。通过大规模预训练得到的"通用"模型，可被微调为各种下游模型。

General Purpose LLM GPLLM

通用大语言模型。面向广泛场景，如 GPT、Claude、Gemini。

Vertical / Domain Model

垂直/行业模型。专注某一领域（医疗、法律、代码）的大模型，通常由基础模型微调而来。

Agent / AI Agent

智能体。能自主感知环境、规划任务、调用工具的 AI 系统，是 2025-2026 年最大的产品叙事。

Function Calling FC

函数调用。模型输出结构化的"调用指令"，让外部系统执行实际操作，是 Agent 的核心能力。

Tool Use

工具使用。模型调用外部 API/工具完成特定任务（搜索、计算、读写文件），扩展模型的能力边界。

Multi-modal MM

多模态。同时处理文本、图像、音频、视频等多种输入输出模式。

Text-to-Image / T2I

文生图。根据文本描述生成图像，代表模型有 Stable Diffusion、FLUX。

Text-to-Video / T2V

文生视频。根据文本描述生成视频，是 2024-2025 年最热门的 AI 赛道之一。

Open Source vs. Closed Source

开源 vs 闭源。开源模型（MIT/Apache）可商用、可二次开发；闭源模型仅能通过 API 调用。

Frontier Model

前沿模型。代表当前技术最高水平的模型，通常由头部公司发布，具有战略意义。

🎯 给产品经理的 3 条核心建议

  1. 不要只看单一分数：MAU 需多源交叉验证，Benchmark 需结合任务场景解读。
  2. 关注"单位经济学"：Token 成本下降速度 > 模型能力提升速度，这是 AI 产品盈利的关键窗口。
  3. 框架 > 工具：掌握底层方法论（多源三角测量、置信区间、归因分析），工具只是实现手段。
